# Workshop Prose Style Guide

**Version**: 1.0  
Canonical reference for all prose style rules in workshop content generated by the OODA pipeline.  
All rules apply to `.adoc` module pages. Rules P.1–P.4 are REQUIRED.

---

## P.1 — Module Summary Format

Every module page MUST end with a `== Module summary` section using exactly this structure:

```asciidoc
== Module summary

**What you accomplished:**

* Past-tense action verb phrase.
* Past-tense action verb phrase.
* Past-tense action verb phrase.

**Key takeaways:**

* Present-tense declarative fact.
* Present-tense declarative fact.
* Present-tense declarative fact.

**Next steps:**

One or two sentences of prose linking to the next module. Never bullets here.
```

Rules:
- Exactly three bullet points per **What you accomplished** and **Key takeaways** block.
- **What you accomplished** bullets use past tense ("Deployed", "Configured", "Verified").
- **Key takeaways** bullets use present tense, declarative ("KServe routes inference traffic…").
- **Next steps** is always prose — never a bulleted list.
- The conclusion module omits **Next steps** (there is no next module).

**Bad example** (vague, unformatted, incomplete):
```asciidoc
== Summary

In this module you installed RHOAI and verified the operator was running.
See the next module for model serving.
```

**Good example**:
```asciidoc
== Module summary

**What you accomplished:**

* Deployed the Red Hat OpenShift AI operator from OperatorHub.
* Configured the DataScienceCluster resource to enable the default dashboard and workbenches.
* Verified the operator pods reached a running state in the `redhat-ods-operator` namespace.

**Key takeaways:**

* RHOAI is installed as an OpenShift operator — its lifecycle is managed by OLM.
* The DataScienceCluster resource is the single control plane for enabling or disabling RHOAI components.
* Dashboard availability is a reliable signal that the full operator stack is healthy.

**Next steps:**

In the next module you will deploy a model-serving platform and route external inference traffic to a running model endpoint.
```

## P.2 — Transition Text Between Exercises

Every exercise boundary (the space between one `== Exercise N` section ending and the next `== Exercise N+1` heading) MUST contain at least one bridging sentence. This sentence goes after the `=== Verify` block, before the next heading.

Use one of three formulas:

### Formula 1: Callback-then-pivot

> "Now that you've [completed action], let's [do next action]."

Example:
```asciidoc
=== Verify

✓ Route responds 200 OK +
✓ Token is present in the response body

Now that you've confirmed the endpoint is live, let's configure rate-limiting so the gateway enforces per-user quotas.

== Exercise 3: Configure rate limits
```

### Formula 2: Problem-then-purpose

> State the gap the learner has just created or discovered, then state what the next exercise closes.

Example:
```asciidoc
=== Verify

✓ Model is serving requests +
✓ Latency is under 500 ms

The current deployment has no autoscaling — a single replica will saturate under load. Exercise 4 adds KEDA-based horizontal scaling tied to queue depth.

== Exercise 4: Add KEDA autoscaling
```

### Formula 3: Forward reference

> "You will explore this further in Exercise N."

Use this at the end of a conceptual aside or NOTE block — not as the primary transition formula.

Example:
```asciidoc
NOTE: The `oc process` / `oc annotate` workaround is required because the UI does not yet expose this field. This is a CLI-vs-UI gap, not a configuration error. You will see this pattern again in Exercise 5.
```

**Bad example** (no transition, abrupt heading change):
```asciidoc
=== Verify

✓ Token is exported

== Exercise 3: Configure rate limits
```

## P.3 — Workaround Handling

Whenever a lab step involves a known deviation, error, or workaround, follow this exact pattern:

1. **NOTE or WARNING _before_ the command** — brief statement of what will happen and that it is expected.
2. **"This is expected."** — explicit reassurance in the admonition body.
3. **One sentence why** — the reason, in plain language.
4. Then the command block.
5. If deeper explanation is needed → `[%collapsible]` block, never inline prose.

```asciidoc
NOTE: The first `oc apply` will return a `NotFound` error for the `InferenceGraph` CRD.
This is expected. The CRD is created by the KServe controller on first apply, so a second
apply is always required.

. Apply the manifest (twice):
+
[source,role="execute"]
----
oc apply -f inferenceservice.yaml
oc apply -f inferenceservice.yaml
----
```

**Bad example** (explanation after the command, buried in prose):
```asciidoc
. Apply the manifest:
+
[source,role="execute"]
----
oc apply -f inferenceservice.yaml
----
+
You may see a `NotFound` error here. This is because the CRD is created by the KServe
controller on first apply, so you need to run the command a second time. This is a known
issue with the operator initialization order. Red Hat is tracking this upstream.
[source,role="execute"]
----
oc apply -f inferenceservice.yaml
----
```

**Collapsible for optional depth:**
```asciidoc
NOTE: The Authorino CA trust patch is required due to a certificate propagation gap. This is expected.
The gateway sidecar does not pick up the CA bundle from the cluster trust store automatically.

. Patch the CA bundle:
+
[source,role="execute"]
----
oc patch ... --patch '{"spec": ...}'
----

[%collapsible]
.Why is the CA patch needed? (optional reading)
====
Authorino validates JWTs against an OIDC endpoint secured by the cluster's internal CA.
The gateway Envoy sidecar runs in a separate trust domain and must be told about this CA
explicitly via the patch. This is tracked in upstream issue #1234.
====
```

## P.4 — Admonition Usage (when to use which)

Use the correct admonition type — do not substitute one for another.

| Admonition | When to use | Example trigger |
|---|---|---|
| `TIP` | Orientation, persona framing, practical shortcuts, "did you know" context | Explaining what the RHOAI dashboard _is_ before the learner opens it for the first time |
| `NOTE` | Non-determinism, expected friction, key conceptual asides, "this is expected" | A pod that takes 3–5 min to come up; a CLI-vs-UI gap |
| `IMPORTANT` | Structural, safety, or ordering callouts the learner must not miss | "Run these commands in order — the second depends on output from the first" |
| `WARNING` | Destructive or irreversible operations; operations with significant side effects | Deleting a namespace; patching cluster-scoped resources |

**TIP — correct use** (orientation before opening the dashboard):
```asciidoc
TIP: The RHOAI dashboard is your primary interface for creating workbenches and data science projects.
It runs as a separate web application from the OpenShift console — you will need both open in this module.
```

**TIP — incorrect use** (this is non-determinism, should be NOTE):
```asciidoc
TIP: The pod may take a few minutes to start. Wait for it to reach Running before proceeding.
```

**NOTE — correct use** (expected friction):
```asciidoc
NOTE: Synchronization between the operator and the DataScienceCluster can take 3–5 minutes.
This is expected — wait for all pods in `redhat-ods-applications` to reach Running before continuing.
```

**WARNING — correct use** (destructive):
```asciidoc
WARNING: This step deletes the `rhoai-demo` namespace and all resources within it.
Ensure you have completed all exercises before proceeding.
```

**IMPORTANT — correct use** (ordering constraint):
```asciidoc
IMPORTANT: Export `$DEPLOY_NAME` before Exercise 4. The variable is used in `oc rollout` commands
that reference the deployment by name — running Exercise 4 without it will fail.
```

## Quick Reference

| Rule | Where it applies | Key phrase |
|---|---|---|
| P.1 | End of every module page | `**What you accomplished:**` / `**Key takeaways:**` / `**Next steps:**` |
| P.2 | Between every pair of `== Exercise N` headings | Transition sentence after `=== Verify` |
| P.3 | Any workaround or unexpected behavior | NOTE _before_ command → "This is expected." |
| P.4 | Any admonition block | Match the type to the intent, not the urgency |
